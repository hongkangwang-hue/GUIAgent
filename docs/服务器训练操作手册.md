# 训练操作手册（服务器）

> 2026-08-27 生成。数据、依赖、基座模型都已就位，照着做即可。

## 0. 开机前

在 AutoDL 控制台把实例**从无卡模式关机，改成 RTX 4090 开机**。
数据盘 `/root/autodl-tmp` 的内容不会丢。

## 1. 连上去，确认 GPU 到位

```bash
nvidia-smi
```

要能看到 `RTX 4090` 和 `24564MiB`。看不到就是还在无卡模式。

## 2. 确认环境（30 秒，值得做）

```bash
cd /root/autodl-tmp/gui-agent
python -c "import torch; print(torch.__version__, torch.cuda.get_device_name(0))"
```

应输出 `2.8.0+cu128 NVIDIA GeForce RTX 4090`。

## 3. 开训 —— **必须用 screen**

SSH 一断，前台进程就会被杀。2 小时的训练必须挂在 screen 里。

```bash
screen -S train
cd /root/autodl-tmp/gui-agent
python -m finetune.train_lora \
    --model /root/autodl-tmp/ms-cache/Qwen/Qwen2.5-VL-3B-Instruct \
    --save-every 50
```

启动后**必须确认这一行**：

```
总步数 446    预热 13 步    每 50 步存一次
```

**不是 446 就按 Ctrl+C 停下来**，说明数据没读对。

### screen 的三个操作

| 要做什么 | 按什么 |
|---|---|
| 离开但让它继续跑 | `Ctrl+A` 然后按 `D` |
| 回来看进度 | `screen -r train` |
| 列出所有会话 | `screen -ls` |

**`Ctrl+A` 再 `D` 之后可以直接关终端、断网、关电脑**，训练照跑。

## 4. 中途看一眼速度

回到 screen 后看进度条：

```
  4%|███              | 20/446 [XX:XX<Y:YY:YY, ZZ.Zs/it]
```

4090 上预计 **15~20 秒/步**，446 步约 **2~2.5 小时**。
如果 `ZZ.Zs/it` 明显更大，回来告诉我。

## 5. 训练完成的标志

```
  adapter 已保存到 finetune/outputs/<时间戳>/adapter
```

看到这行才算完。

## 6. 下载权重回本机

先在服务器上删掉不需要的 checkpoint（能省很多传输时间）：

```bash
cd /root/autodl-tmp/gui-agent/finetune/outputs
ls                                    # 看时间戳目录叫什么
rm -rf <时间戳>/checkpoint-*
du -sh <时间戳>                       # 应该只剩 150 MB 左右
```

然后**在你本机的 PowerShell**（不是服务器终端）里：

```powershell
cd d:\GUIAgent
scp -P 13036 -r root@connect.westc.seetacloud.com:/root/autodl-tmp/gui-agent/finetune/outputs/<时间戳> finetune\outputs\
```

`-P` 是**大写**。

### 要下载的只有两样

```
finetune/outputs/<时间戳>/adapter/            约 150 MB
finetune/outputs/<时间戳>/train-stats.json    报告要用
```

## 7. 下载完，本机评测

```powershell
cd d:\GUIAgent
conda activate gui-agent
python -m eval.action --local Qwen/Qwen2.5-VL-3B-Instruct ^
    --adapter finetune\outputs\<时间戳>\adapter --tag after-放宽
```

**别只看总体准确率。** 训练集里 `done` 占 41.6%，模型只要学会多输出
`done` 总分就能涨，而那是退步。要分动作类型看：

| 看什么 | 为什么 |
|---|---|
| `type` 准确率 | 报告 §10.9 的瓶颈，训练集从 0 变成 216 条 |
| `done` **误报率** | 该继续时喊停 = 任务直接失败 |
| `left_click` 坐标误差 | 回归风险最大处，会不会被新动作挤掉 |

## 8. 确认无误后再释放实例

**下载完、本机能加载 adapter 之后**再去控制台释放实例。
释放后数据盘内容全部清空，不可恢复。

### 两个踩过的坑

**① HuggingFace 下载卡死。** 新版 `huggingface_hub` 默认用 Xet 分块传输，
它直连 `xethub.hf.co`**绕过镜像**，结果 401 Unauthorized。即使设了
`HF_ENDPOINT=https://hf-mirror.com` 也没用，必须同时
`export HF_HUB_DISABLE_XET=1`（已写进 `~/.bashrc`）。

**② 后来干脆换了 ModelScope。** 实测下载速度：

```
ModelScope 魔搭         15.28 MB/s     ← 采用
hf-mirror                0.88 MB/s
HuggingFace + 学术加速    0.42 MB/s
```

Qwen 是阿里自家模型，魔搭是第一方渠道，国内节点。所以第 3 步的
`--model` 指的是 ModelScope 的本地路径，不是 HF 模型名。
**权重完全相同**，只是来源不同。
