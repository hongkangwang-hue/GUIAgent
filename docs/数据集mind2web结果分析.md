# Multimodal-Mind2Web 截图尺寸分析与清洗阈值推导

> 数据源：`osunlp/Multimodal-Mind2Web`，train split
> 测量日期：2026-08-27
> 目的：为「ScreenAgent 为主、Mind2Web 为辅」的消融实验确定样本清洗阈值
> **阈值由实测分布 + 下游判据推出，不是预先指定的**

---

## 0. 一句话结论

**页高 ≤ 3000 px。** 全量 7775 条中保留 2830 条（36.4%），
目标元素可读率 78%，是「不损失清晰度的前提下能拿到的最多数据」的拐点。

---

## 1. 先记一次错判

在本次测量之前，我基于 **42 张抽样** 得出过一个结论：

> 「Mind2Web 里不存在『普通网页截图』这个群体。它的采集方式就是整页滚动截图
> —— 不是有些页长有些页正常，而是全部按整页拍。」

**这个结论被全量数据直接推翻。**

| 我当时说的 | 全量实测 |
|---|---|
| 宽高比 1.2~2 这一档：0 张（0%） | P10 宽高比 = **1.31**，正落在这一档 |
| 「不存在接近视口的截图」 | **P0 = P1 = 1080 px**，即 1280×1080 的一屏页面确实存在 |

失误原因不是判断错，是**样本量不足以看见那一档**。n=42 时一个占比 3~5% 的分箱
抽到 0 张属于正常波动，我却把它当成了「该群体不存在」的证据。

**留痕理由：这与 M2 阶段「按 X 铺开只保证 X 这一维无偏」是同一类错误——
用一个不足以支撑结论的样本去下全称判断。**

### 2.5 关键观察：**没有天然断点**

分布是**单峰 + 右长尾**，众数在 4k~5k，不是「普通网页」和「超长网页」两坨。

所以：

- 「剔除超长网页」在数据上**成立**——长尾确实存在（P99 = 18364 px，最长 44771 px）

**结论：阈值不能从直方图形状读出来，必须挂在一个下游判据上。**

## 3. 下游判据：目标元素缩放后还剩多少像素

### 3.1 判据来源

训练时图像会被压到 `max_pixels = 896×896 = 802816`：

```
缩放系数 = sqrt(max_pixels / (W × H))          （Qwen2-VL smart_resize 等效）
```

Qwen2-VL 视觉 patch 为 14 px，`merge_size = 2`，
**一个视觉 token 覆盖 28 px**。目标元素缩到 28 px 以下，
垂直方向连一个 token 都占不满——模型不是「定位不准」，是看不见。

于是取两条线：

| 线 | 含义 |
|---|---|
| 元素高 ≥ 28 px | 占满一个视觉 token |
| 元素高 ≥ 14 px | 占半个视觉 token（可读下限） |

### 3.2 样本

抽 **1121 条**真实 `pos_candidates[0].bounding_box_rect`，
按 `idx` 均匀铺满 0~7775（60 批 × 20 条），不集中在开头。

### 3.3 目标元素本身就很扁

原图（1280 宽坐标系）中的目标元素尺寸：

| | P10 | P25 | 中位 | P75 | P90 |
|---|---:|---:|---:|---:|---:|
| 宽 | 37 | 79 | **160** | 275 | 408 |
| 高 | 18 | 24 | **37** | 49 | 62 |

缩放后：

| | P10 | P25 | 中位 | P75 | P90 |
|---|---:|---:|---:|---:|---:|
| 宽 | 14.2 | 29.3 | **68.2** | 125.1 | 193.6 |
| 高 | 6.3 | 9.9 | **15.2** | 21.5 | 29.5 |

**网页链接/按钮天生是扁的**——中位高度在原图里就只有 37 px。
这不是缩放造成的，缩放只是把它从「扁」变成「几乎不可见」。

## 4. 阈值推导

### 4.1 口径 A：按页高筛

| 规则 | 保留率 | 折算全量 | 元素高 ≥28px | 元素高 ≥14px |
|---|---:|---:|---:|---:|
| 页高 ≤2000 | 14.6% | 1137 | 35% | 79% |
| 页高 ≤2500 | 26.8% | 2081 | 26% | 81% |
| **页高 ≤3000** | **36.4%** | **2830** | 25% | **78%** |
| 页高 ≤3500 | 45.9% | 3572 | 21% | 75% |
| 页高 ≤4000 | 50.4% | 3919 | 19% | 72% |
| 不筛 | 100% | 7775 | 12% | 55% |

**拐点在 3000：**

- ≤2000 / ≤2500 / ≤3000 三档的可读率都是 **78~81%**——
  卡得再严，数据少一半，清晰度一点没多
- 从 **3500 起才开始单调下降**（75 → 72 → 70 → 66）

所以 **3000 = 不损失清晰度的前提下能拿到的最多数据**。

### 4.2 口径 B：直接按缩放后元素高筛（页高不限）

| 规则 | 保留率 | 折算全量 | 中位页高 | 页高 P90 |
|---|---:|---:|---:|---:|
| 元素高 ≥14 | **54.4%** | **4231** | 2921 | 5429 |
| 元素高 ≥20 | 29.2% | 2268 | 2597 | 5234 |
| 元素高 ≥28 | 12.0% | 936 | 2173 | 4923 |

口径 B 保留下来的样本，页高分布：

```
 0k~2k   21.0%
 2k~4k   46.1%
 4k~6k   26.7%
 6k~8k    5.2%
8k~10k    0.8%
 >=10k    0.2%
```

### 4.3 选 A 不选 B

**B 在两个指标上都赢**：留下更多数据（4231 vs 2830），
且按定义 100% 可读（vs 78%）。

**但仍然选 A**，理由：

| | 口径 A（页高） | 口径 B（元素高） |
|---|---|---|
| 筛选依据 | 页面级属性，**与标签无关** | **按标签筛**——只留目标够大的样本 |
| 评估偏差 | 无 | 挑软柿子，未筛数据上评估会系统性偏乐观 |
| 与要求的一致性 | 就是「剔除超长网页截图」这条规则 | 是另一条规则 |

**B 是选择在结果上（selection on the outcome）。** 训完的模型在未清洗数据上
的表现会比清洗集上差，而我们无法区分这是「跨域难」还是「筛选造的假象」。

### 4.4 备选：A ∩ B

`页高 ≤3000 且 元素高 ≥14` —— 约 **2200 条**，
仍是 20% 混入需求（445 条）的 **5 倍**。

如果消融在纯 A 下是负结果，可以用这一档再试一次，
用来区分「跨域本身不行」和「清晰度不够」。

### 4.5 供给完全不是约束

混入 20% 到 1783 条 ScreenAgent 执行器样本，需要约 **445 条**。

| 口径 | 折算全量 | 是需求的 |
|---|---:|---:|
| 页高 ≤3000 | 2830 | **6.4 倍** |
| 元素高 ≥14 | 4231 | 9.5 倍 |
| 页高 ≤2000（最严） | 1137 | 2.6 倍 |

**即使卡到最严的 ≤2000 也够用。**

## 5. 一个必须先说的不利事实

```
即使卡到 <=3000，只有 25% 的目标能占满一个视觉 token
缩放后目标元素中位高 = 19.9 px

对照 ScreenAgent：1024 × 768 = 786432 <= 802816
                  → 缩放系数 1.00，一个像素都不缩
```

**桌面数据完全不缩放，网页数据缩到约 0.5 之后还只有 1/4 的目标够一个 token。**

这个差距**清洗缓解不了**——它来自两个数据集采集方式的根本差异
（桌面截一屏 / 网页截整页）。

**所以消融很可能是负结果。** 这不是实验设计的问题：
「效果差就不纳入」这条判定规则正好接得住这种情况。

**预先写下这个预期，是为了避免事后把负结果解释成别的原因。**

---

## 6. 一个必须报出来的混杂变量

train split 只有三个 domain：

| domain | 条数 | 中位高度 | ≤2000 | ≤3000 | ≤4000 |
|---|---:|---:|---:|---:|---:|
| Travel | 4082 | 3738 | 18% | **36%** | 54% |
| Shopping | 2309 | 4962 | 11% | **23%** | 37% |
| Entertainment | 1384 | 4204 | 13% | **28%** | 45% |

**Shopping 页面天生更长**（中位 4962，比 Travel 高 1224 px），
按高度卡会系统性少收 Shopping。

清洗后领域配比变了。**报告里必须报出清洗前后的 domain 分布**，
否则「加了 Mind2Web」这个变量里混着「领域分布也变了」，
不再是单变量实验。

## 7. 消融实验设计

```
档 A   ScreenAgent only                                  基准（尚未跑出）
档 B   ScreenAgent + Mind2Web(页高<=3000) 混入 20%
```

判定规则（沿用「一主一副」的思路）：

- 定位成功率**优于**档 A → 纳入
- 定位成功率**劣于或持平**档 A → 不纳入，记录负结果

补充要求：

1. **单变量**——只改数据，超参数与档 A 完全一致
2. **报出清洗前后的 domain 分布**（见 §6）
3. 若为负结果，可再跑一档 `A ∩ B`（§4.4）区分成因

### 前置阻塞

**档 A 的基准尚未取得。** 上一轮训练因
`SYSTEM_PROMPT` 动作集不全、标签掩码偏移 3 个 token 两个 bug 作废，
修好的 `finetune/train_lora.py` 尚未上传重训。

**基准没有，消融没有比较对象。** 这是本方案的第一顺位依赖。

## 8. 复现

### 8.1 数据获取

不下载任何图片本体，只取 HF datasets-server 的列元数据：

```python
# 全量尺寸（7775 条）
"https://datasets-server.huggingface.co/rows"
"?dataset=osunlp%2FMultimodal-Mind2Web&config=default&split=train"
"&columns=screenshot,website,domain,annotation_id"
"&offset={offset}&length=100"
# screenshot 列返回 {"src":..., "height":..., "width":...}

# bbox 抽样（1121 条）
"&columns=pos_candidates,screenshot&length=20"
# pos_candidates[0].attributes.bounding_box_rect = "x,y,w,h"
```

注意事项：

- `length=100` 时会撞 **HTTP 429**，需指数退避重试
- 拉 `pos_candidates` 时载荷大，`length` 降到 20
- 全量拉取约需 12~15 分钟，建议做断点续传（按已有最大 `idx` 续）

### 8.2 产物

| 文件 | 内容 |
|---|---|
| `m2w_train_dims.jsonl` | 7775 条全量：`idx / w / h / website / domain / annotation_id` |
| `m2w_bbox.jsonl` | 1121 条抽样：`idx / img_w / img_h / el_x / el_y / el_w / el_h / tag` |

> 本次产物落在会话 scratchpad 下。若要长期保留，
> 应移入仓库并记入 `docs/`，因为 §4 的阈值结论依赖它们。

## 9. 本文档不声称的事

- **不声称 3000 是唯一正确的阈值。** 它是在
  「`max_pixels=896²` + Qwen2-VL 28px token」这一组具体设定下推出来的。
  换 `max_pixels` 或换模型，拐点会移动。
- **不声称 1121 条 bbox 抽样等同全量。** 高度分布是全量（7775），
  但元素尺寸是抽样（14.4%）。§4 的可读率数字带抽样误差。
- **不声称 `pos_candidates[0]` 一定是真实目标。** 取的是第一个正候选，
  多正候选的样本未做进一步核对。
- **不声称清洗后 Mind2Web 一定有用。** §5 已写明预期偏负，
  结论以消融实验为准。
