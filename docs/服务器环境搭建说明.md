# 服务器环境搭建说明

> 面向 M3（LoRA 微调、批量评测、模型部署）。
> 配套文件：`requirements-server.txt`

---

## 1. 服务器承担什么，不承担什么

**这是本文档最重要的一节。** 搞错分工会浪费大量时间在注定跑不起来的东西上。

本项目的感知与控制层是 **Windows + 真实桌面**专有的。服务器（通常是无头
Linux）跑不了这部分，也不该跑。

| 模块 | 跑在哪 | 原因 |
|---|---|---|
| `perception/` | **本地 Windows** | dxcam 走 DXGI、uiautomation 是 Win32 API、DPI 感知同理 |
| `control/` | **本地 Windows** | pyautogui / pynput 需要真实桌面，无头环境 import 就失败 |
| `core/loop.py` | **本地 Windows** | 它要驱动真键鼠 |
| `cli/` | **本地 Windows** | 同上 |
| `finetune/`（M3 新建） | **服务器** | 吃显存，不需要桌面 |
| `eval/`（M3 新建） | **服务器** | 批量挂机，不需要桌面 |
| 数据集处理 | 服务器 | 直接从 HF/ModelScope 下，比本地传快 |
| 微调模型推理 | 两边都行 | 见第 6 节的重要区分 |

CI 配置里那句话说的就是这件事：

> 用 Windows runner：本项目的感知与控制是 Windows 专有的（uiautomation、
> DPI 感知、dxcam），在 ubuntu 上连导入都过不去。

**结论：服务器不是"换个地方跑同一套东西"，是接管 GPU 那部分。**
GUI Agent 的执行端永远在本地。

## 2. 开工第一件事：把这几个数记下来

进服务器先跑这几条，结果填进表里。**后面所有决策都依赖这些数**，尤其
`memory.free`——M3 能不能本地训练是按可用显存判断，不是标称显存。

```bash
# 显卡型号、算力、显存
nvidia-smi --query-gpu=name,compute_cap,memory.total,memory.free,driver_version --format=csv

# 驱动支持到哪个 CUDA 版本（看右上角 "CUDA Version"）
nvidia-smi | head -4

# 系统与 Python
cat /etc/os-release | head -2
python3 --version

# 磁盘：模型权重很占地方，先确认容量
df -h ~
```

| 项 | 实测值 | 说明 |
|---|---|---|
| 显卡型号 | | |
| 算力 `compute_cap` | | 决定 torch 的 cu 版本，见第 3 节 |
| `memory.total` | | 标称值，**不用它做判断** |
| `memory.free` | | **按这个判断能跑多大模型** |
| 驱动版本 / 支持 CUDA | | 驱动决定上限，装更高的 cu 版会崩 |
| 可用磁盘 | | Qwen2.5-VL-3B 权重约 7GB（fp16），7B 约 16GB，9B/11B 各 20GB+ |
| 系统 / Python | | |

**磁盘容量要认真算。** M3 任务 6 的短租实测要同时放 GLM-4V-9B 与
Llama 3.2 Vision 11B，M3 文档给的估计是 **60-80GB**。如果服务器盘小，
要么分批下载删除，要么改用量化权重。

## 3. 装 torch：唯一容易装错且不报错的一步

**torch 的 cu 版本必须匹配显卡算力与驱动。装错不会报错，而是"能导入、
一运算就崩"。** 本项目在开发机上已经踩过一次（Blackwell sm_120 装了
cu121，详见 `docs/开发环境配置文档.md` 第 3 节）。

对照表：

| 算力 | 典型显卡 | torch 索引 |
|---|---|---|
| sm_75 | T4 | `cu121` |
| sm_80 | A100 | `cu121` |
| sm_86 | RTX 30xx / A10 | `cu121` |
| sm_89 | RTX 40xx / L4 / L40S | `cu121` 或 `cu124` |
| sm_90 | H100 | `cu124`+ |
| sm_120 | RTX 50xx / Blackwell | `cu128`+（需 torch 2.7+） |

**两个约束同时成立才行**：算力要求的最低 cu 版本 ≤ 你装的版本 ≤ 驱动支持
的最高 cu 版本。

```bash
# 以 cu121 为例，按上表替换
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

装完立刻验：

```bash
python -c "
import torch
print('torch      :', torch.__version__)
print('cuda 可用  :', torch.cuda.is_available())
print('设备       :', torch.cuda.get_device_name(0))
print('算力       :', torch.cuda.get_device_capability(0))
x = torch.randn(1000, 1000, device='cuda')
print('矩阵乘验证 :', (x @ x).sum().item())   # 这一步才真正验证算力匹配
"
```

**最后那步矩阵乘不能省。** `cuda.is_available()` 返回 True 只说明驱动
认得显卡，算力不匹配时它照样返回 True，直到真正算一次才崩。

## 4. 拿代码：用 git，不要手动传

```bash
git clone <仓库地址> && cd GUIAgent
```

之后每次同步就是 `git pull`。

**不要用 scp / rsync 整目录传。** 两边会各自漂移，几天后就分不清服务器上
跑的是哪个版本——而 M3 验收标准 3 明确要求「评测脚本可一键复现」，
版本对不上这条就没法过。

### 环境与依赖

```bash
# conda 或 venv 都行，与本地保持同一个 Python 版本（3.10）
conda create -n gui-agent python=3.10 -y
conda activate gui-agent

# 先按第 3 节装 torch，再装其余
pip install -r requirements-server.txt
```

**不要用 `requirements.txt`。** 那份含 Windows 专有与桌面依赖的包，
在无头 Linux 上会失败或装一堆用不上的东西（原因见 `requirements-server.txt`
文件头的说明）。

### `.env`

`.env` 在 `.gitignore` 里（第 2 行），**不会跟着 git 过去**，服务器上要
单独建：

```bash
cp .env.example .env
```

服务器上只需要填**跑批量横评用的 API key**（M3 任务 8 的档 3-6）。
训练和本地推理不需要任何 key。

## 5. 验证环境：只跑得动一半的测试

服务器上 `pytest tests/` 会**收集失败**——`tests/test_capture.py` 等文件
在 import 阶段就会去加载 dxcam / uiautomation。这是预期行为，不是环境
装坏了。

只跑不依赖桌面的那部分：

```bash
pytest tests/test_parsing.py tests/test_backends.py \
       tests/test_trajectory.py tests/test_openai_compat.py -q
```

它们覆盖 `llm/`、`grounding/`、`core/trajectory.py` 的纯逻辑部分，依赖链
上没有任何 Windows API：

- `perception/dpi.py` 只 import `ctypes`（跨平台），Windows 调用全部被
  `IS_WINDOWS` 守卫，非 Windows 下退化为空操作
- `perception/capture.py` 的 dxcam / mss 都是惰性导入
- `control/actions.py`、`perception/types.py` 纯标准库

**这四个全过，说明代码同步正确、依赖装对了。**

然后试一下 `test_loop.py`：

```bash
pytest tests/test_loop.py -q
```

它 import 了 `control.executor`，但 **pyautogui 与 pynput 都是惰性导入**
（`executor.py` 在 `_ensure_pyautogui()` 方法里才 import），而这些用例走
的是 `dry_run=True` 路径，不会触发。**理论上能过**——过了更好，说明 Loop
的编排逻辑在服务器上也可验证；不过也不影响 M3，它的正确性由本地 Windows
CI 保证。

真正跑不了的是感知控制相关的那几个：`test_capture.py`、`test_actions.py`、
`test_executor.py`、`test_safety.py`、`test_coordinate.py`、
`test_perception_pipeline.py`、`test_eval_recall.py`、`test_types.py`。

## 6. 推理服务：一个必须说清楚的区分

**"本地调用远程服务器" ≠ "本地部署"。**

大纲第 80 行要求「支持开源多模态模型的**本地部署与 API 调用**」，走 HTTP
调服务器只满足后一半。两者用途不同，都要有：

| | 用途 | 满足大纲哪一半 |
|---|---|---|
| 服务器起推理服务，本地 HTTP 调 | M3 开发调试期、批量评测 | API 调用 |
| adapter 下载回本地加载 | 最终交付的**离线版** | 本地部署 |

好在两者不冲突：**LoRA adapter 只有 30-60MB**，训练完从服务器拉回本地
毫无压力。服务器上训练调试，最后把 adapter 拿回本地跑一遍验证即可。

### 起服务（调试期用）

vLLM 原生就是 OpenAI 兼容端点，且支持直接挂 LoRA adapter：

```bash
pip install vllm      # 默认没装，见 requirements-server.txt 末尾

vllm serve Qwen/Qwen2.5-VL-3B-Instruct \
    --enable-lora \
    --lora-modules grounding=/path/to/adapter \
    --host 0.0.0.0 --port 8000
```

### 本地怎么连

**不需要写新的后端类。** 在 `llm/providers.py` 的 `PROVIDERS` 字典里加一条
记录即可——这是当初把后端写成通用 OpenAI 兼容层（而不是绑死某一家）
换来的好处：

```python
"selfhost": Provider(
    key="selfhost",
    label="自建推理服务",
    api_key_env="SELFHOST_API_KEY",      # vLLM 默认不校验，填任意值
    base_url_env="SELFHOST_BASE_URL",
    model_env="SELFHOST_MODEL",
    default_base_url="http://<服务器IP>:8000/v1",
    default_model="grounding",
    notes="自建 vLLM 服务。属于 API 调用，不满足大纲的本地部署要求",
),
```

然后 `.env` 里设 `LLM_PROVIDER=selfhost`，`OpenAICompatBackend` 一行代码
都不用改。

**前提是服务器有公网 IP 或你能建隧道。** 只有内网的话，用 SSH 端口转发：

```bash
ssh -L 8000:localhost:8000 用户名@服务器地址
# 之后本地的 http://localhost:8000/v1 就通到服务器上了
```

## 7. 训练期的实务提醒

**① 用 `tmux` 或 `nohup`，别裸跑。** LoRA 训练 5-8 小时，SSH 断线会把
进程一起带走。

```bash
tmux new -s train
# 在里面启动训练，Ctrl+B 然后按 D 脱离
tmux attach -t train   # 回来看
```

**② checkpoint 每 200 步存一次**（M3 任务 2 已规定）。训练中断不用从头
再来。

**③ 模型权重下载走 ModelScope 更快。** 国内服务器从 HuggingFace 拉
Qwen 权重经常超时：

```bash
pip install modelscope
python -c "from modelscope import snapshot_download; snapshot_download('Qwen/Qwen2.5-VL-3B-Instruct')"
```

**④ 训练前先跑 100-step smoke test。** M2 前置件②就是这个：只验流程能
不能跑通（数据加载 → 前向 → 反向 → 存 checkpoint → 重新载入 adapter），
**不看效果、不调超参**。跑通了才敢启动 5-8 小时的正式训练。

服务器搭好后逐项确认，全绿再开始 M3：

- [ ] `nvidia-smi` 正常，第 2 节的表填完
- [ ] torch 装好，**矩阵乘验证通过**（不只是 `is_available()`）
- [ ] `git clone` 完成，`git log -1` 与本地一致
- [ ] `pip install -r requirements-server.txt` 无报错
- [ ] 第 5 节的四个测试文件全过
- [ ] 磁盘剩余容量 ≥ 计划下载的权重总量 + 20GB 余量
- [ ] `tmux` 可用
- [ ] 模型权重能下载（先试 3B，确认通道通畅）
