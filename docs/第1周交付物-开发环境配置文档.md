## 四、CUDA 加速配置与验证

大纲第 1 周任务明确要求「**配置 CUDA 加速（如有 GPU）**」。本机为 Blackwell 架构，该项需要额外判断，过程如下。

### 4.1 版本选择依据

RTX 5060 是 Blackwell 架构，算力 **sm_120**。PyTorch 的每个 `cuXXX` 构建只编译特定几种算力的 kernel，因此 cu 版本必须**同时**满足两个条件：

| # | 条件 | 本机取值 |
|---|---|---|
| ① | 构建包含本卡算力 sm_120 | cu128 起才有，`cu121` 及更早均无 |
| ② | CUDA runtime 不高于驱动上限 | 驱动 572.90 支持至 **CUDA 12.8** |

两者取交集，本机安装 **cu128**：

```powershell
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
```

### 4.2 验证结果（三重判据）

`torch.cuda.is_available()` 不能作为判据——它只检查驱动与运行时能否初始化，不检查是否存在本卡的 kernel。因此采用三重判据：

```python
import torch
print(torch.__version__, torch.version.cuda)          # 2.11.0+cu128  12.8
print(torch.cuda.is_available())                       # True
print(torch.cuda.get_arch_list())                      # 含 'sm_120'
print(torch.cuda.get_device_capability(0))             # (12, 0)
x = torch.randn(1024, 1024, device='cuda')
print((x @ x).sum().item())                            # -1277.005859375（实际跑完）
```

| 判据 | 结果 |
|---|---|
| ① `torch.cuda.is_available()` | ✅ True |
| ② 算力标签在 `torch.cuda.get_arch_list()` 中 | ✅ `sm_120` 在列 |
| ③ GPU 上真实执行矩阵乘 | ✅ 完成，输出 -1277.005859375 |

### 4.3 bitsandbytes 4-bit 量化实测

bitsandbytes 对新架构的 kernel 支持与 PyTorch 是**两件独立的事**，不能只看版本号，因此用小模型实际探路：

```python
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
cfg = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_compute_dtype=torch.bfloat16)
m = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct",
                                         quantization_config=cfg, device_map="cuda:0")
```

**结果：加载成功，显存占用 0.45 GB。** 确认 bitsandbytes 0.50.1 对 Blackwell 的 kernel 支持可用，为第 5 周的 LoRA 微调扫清了工具链障碍。

## 七、环境复现方式

环境可由以下两份文件完整复现：

| 文件 | 用途 |
|---|---|
| `docs/开发环境配置文档.md` | 安装操作指南（含安装顺序约束与故障排查表） |
| `requirements.lock.txt` | 165 个包的精确版本锁定 |

```powershell
conda create -n gui-agent python=3.10 -y
conda activate gui-agent

# torch 必须先装，且 cu 版本按显卡算力与驱动上限选，不可照抄
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128

pip install -r requirements.lock.txt
python scripts/env_check.py
```

**两条顺序约束不可违反**（已写入配置文档）：

1. **torch 必须先于 easyocr 安装**。easyocr 依赖 torch，先装它会导致 pip 拉取 CPU 版 torch 占住依赖，之后 CUDA 版无法装入（依赖已满足，pip 不会主动替换）。
2. **cu 版本必须按本机显卡算力与驱动上限重新判断**，不可套用另一台机器的命令。

> `requirements.lock.txt` 是**机器相关的**，换机器后需重新生成。

## 八、环境搭建中解决的技术问题

本节记录搭建过程中实际遇到并解决的三个问题，均已补充进 `docs/开发环境配置文档.md` 的故障排查表。

### 8.1 独显处于 Code 43 故障状态

**现象**：`nvidia-smi` 报 "insufficient permissions"，改用管理员权限运行结果相同。

**诊断**：该报错具有误导性，真实原因不是权限。经 `Get-PnpDevice` 查得设备处于 `CM_PROB_FAILED_POST_START`（即 Code 43），驱动服务 `nvlddmkm` 未启动。

排除硬件故障的依据：PCI 总线枚举完整、驱动签名有效、30 天内无任何 `nvlddmkm` 崩溃事件——属于"一次都没成功启动"，而非"运行中崩溃"。

**解决**：根因为 **Windows 快速启动**。快速启动采用混合关机，会将设备错误状态连同内核会话一起休眠并跨开机恢复，因此常规的"关机再开机"无效。关闭快速启动后执行完整重启即恢复，**驱动未做任何更换**。

```powershell
Set-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Power" -Name HiberbootEnabled -Value 0
```

### 8.2 PyTorch 的 CUDA runtime 超出驱动支持上限

**现象**：安装 cu130 版 torch 后，`torch.cuda.is_available()` 返回 `False`，报 `cudaErrorNotSupported`。

**诊断**：驱动 572.90 最高支持 CUDA 12.8，而 cu130 需要 CUDA 13.0。**值得注意的是，此时 `torch.cuda.get_arch_list()` 中仍然包含 `sm_120`**，仅核对算力会误判为"版本装对了"。

**解决**：改装 cu128（见第四节）。该失败模式与常见的"构建不含本卡算力"是两回事，症状恰好相反：

| 失败模式 | `is_available()` | 表现 |
|---|---|---|
| 构建不含本卡算力 | 可能为 True | 一执行 GPU 运算就崩溃 |
| runtime 高于驱动上限 | 直接 False | CUDA 根本无法初始化 |

### 8.3 PaddlePaddle 3.3.1 的执行器缺陷

**现象**：OCR 推理崩溃，报 `NotImplementedError: (Unimplemented) ConvertPirAttribute2RuntimeAttribute not support`。

**诊断**：paddlepaddle 3.3.1 的新执行器（PIR）在 oneDNN 路径上存在缺陷。

**解决**：设置环境变量关闭 oneDNN 默认启用。注意 `FLAGS_use_mkldnn=0` 与 `FLAGS_enable_pir_api=0` 均无效，PaddleX 使用独立开关：

```powershell
$env:PADDLE_PDX_ENABLE_MKLDNN_BYDEFAULT = "False"
```
