## 2. 已定的五件事，不再讨论

### ① 建虚拟机 —— 定了，做

M0 全局约束 1 写的是「任何里程碑都不得绕过」，架构 A（Agent 跑在客机内）
你也已经确认过。

我 08-23 一度建议改用「宿主机专用账号」省一小时，**那条建议撤回**。理由有三，
最要命的是第三条：

1. 会让同一条验收标准（M1-6）两周内改第二次；
2. 专用账号不是隔离——同一登录会话，`pyautogui` 打得出 Win+R、Alt+F4；
3. **中途换环境会毁掉数据可比性**。M5 的报告要引用 M2 的单任务成本与成功率
   作参照，两者跑在不同环境的话，要么重跑 M2，要么在报告里解释一堆环境差异。
   这个代价远超一小时。

顺带：客机里改显示缩放不影响宿主机，所以**验收标准 3 的三档 DPI 保持三档**，
不降级。这本来就是建虚拟机的收益之一。

### ② 评估规模改回 20 任务 —— 已改完

大纲 W7 白纸黑字「设计包含 **20 个**不同难度桌面任务的测试集」。
原计划 15 任务是我们自己降的，已全部改回：

- 主评估 20 × 3 = **60 次**
- 难度分层：简单 8 / 中等 8 / 困难 4
- 超时降级预案改为**先降重复次数（20×2），不降任务数**

### ③ 平台表述修正 —— 已改完

M0 原写「仅 Windows 通路可用」，复核代码后发现是过度自贬：截图走 mss、
鼠标键盘走 pyautogui、OCR 走 PaddleOCR / EasyOCR，**三者本身都跨平台，
代码里没有 `sys.platform` 分支**。唯一 Windows 专有的是 UIA 识别通道，
非 Windows 上自动降级为 OCR 单通道。

准确表述：**架构跨平台，仅在 Windows 上验证过**。这已满足大纲 W2 任务 1
「实现跨平台屏幕实时截图功能」，不构成偏差。

### ④ M3 不做额外削减 —— 复核后撤回

我 08-23 曾提出两条削减：横评六档降三档、模式 B 降为「有余力才做」。
**逐条核对 M3 文档后撤回，因为 M3 原本就已经把这两件事处理得更好。**

| 我提的 | M3 原文 | 结论 |
|---|---|---|
| 横评六档 → 三档 | 验收标准 3：「档 1、2、4 **必须完成**，其余三档尽量覆盖、目标六档全覆盖」 | 已是分级要求，不是硬性六档。**且横评是 P1「挂机批量跑，人力成本很低」——我砍的是最便宜的那件事** |
| 模式 B 降为可选 | 验收标准 7：「(a) 跑通并产出对比数据 / (b) 未跑通但有明确技术原因记录与离线对比数据」；降级路径 3：「接入超时（**D5 结束**仍未跑通）→ 停止接入，降级为离线评测组件」 | 已是可选带兜底，且已有**日期式**截止线，比我的「有余力才做」更可执行 |

M3 的优先级表把人力分配写得很清楚：

| 优先级 | 内容 | 说明 |
|---|---|---|
| P0 | 3B 本地部署 + LoRA + ScreenSpot 档 1/2/4 | 大纲 W5 核心，不可降级 |
| P0 | `LocalVLMGrounding` 实现与接入 | **本周最吃人力** |

优先级来释放，那套机制比我事后一刀切更贴合实际。

> 教训记在这：被要求「砍到只满足大纲」时，我下意识去砍看起来最显眼的东西
