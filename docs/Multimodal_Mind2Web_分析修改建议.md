# Multimodal-Mind2Web 截图尺寸分析：修改建议与复核重点

> 用途：基于现有《Multimodal-Mind2Web 截图尺寸分析与清洗阈值推导》文档，整理需要进一步修改、验证和补充的重点，供后续继续完善实验设计。

## 1. 总体判断

现有分析整体方向是合理的，已经能够支持“先跑 ScreenAgent 基准，再把清洗后的 Multimodal-Mind2Web 作为第二阶段增量数据做消融实验”的方案。

当前最有价值的结论包括：

- 全量统计推翻了“Mind2Web 不存在普通长度截图”的早期判断。
- Mind2Web 高度分布是单峰右长尾，没有天然的“普通网页 / 超长网页”分界。
- 因此清洗阈值不能仅凭直方图决定，而需要结合模型实际视觉预处理后的可读性。
- 按目标元素大小筛选虽然能留下更多“容易样本”，但会引入标签相关的选择偏差，因此主方案采用页面高度筛选更合理。
- 高度筛选会改变 Travel / Shopping / Entertainment 的 domain 配比，这个混杂变量必须报告。
- 当前最优先事项仍然是先修复 ScreenAgent 训练问题并取得 baseline；没有 baseline，Mind2Web 消融没有比较对象。

## 2. 最需要修改的一点：不要把 3000 px 写成“唯一拐点”

现文档把“页高 ≤3000 px”表述为：

> 不损失清晰度的前提下能拿到的最多数据的拐点。

这个说法略强。

现有数据：

| 页高阈值 | 保留率 | 元素高 ≥14 px |
|---|---:|---:|
| ≤2000 | 14.6% | 79% |
| ≤2500 | 26.8% | 81% |
| ≤3000 | 36.4% | 78% |
| ≤3500 | 45.9% | 75% |
| ≤4000 | 50.4% | 72% |

从这组数据看，3000 px 是一个合理折中，但并不是数学意义上非常明确的断点。

建议改成：

> **在当前 `max_pixels = 896×896` 和 Qwen2-VL 视觉预处理设定下，页高 ≤3000 px 是一个较合理的折中阈值：可保留约 36.4% 的训练动作样本，同时将目标元素缩放后高度 ≥14 px 的比例维持在约 78%。**

这样既保留结论，又避免过度宣称。

## 3. “普通长度截图存在”应保留为核心发现

这次全量统计最重要的纠正之一，是证明 Multimodal-Mind2Web 中确实存在相对短的网页截图。

关键数据：

- P0 = 1080 px
- P1 = 1080 px
- P5 = 1162 px
- P10 = 1680 px
- P25 = 2666 px

因此建议明确写成：

> **Multimodal-Mind2Web 并非全部由超长整页截图构成，数据中确实存在接近普通视口长度的网页截图，因此不能因为部分样本过长而整体排除该数据集。**

这也是“先清洗、再做消融”方案最重要的数据依据。

## 4. 保留“页面级筛选优先于目标元素级筛选”的判断

现文档比较了两种方案：

- A：按页面高度筛选
- B：按缩放后的目标元素高度筛选

虽然 B 能留下更多数据，而且理论上目标可读率更高，但 B 直接依赖标签中的目标元素尺寸，会系统性偏向更容易定位的样本。

这个判断建议保留。

主方案：

```text
Mind2Web
→ 按页面高度清洗
→ 保留 ≤3000 px
→ 再进入增量训练
```

不建议直接采用：

```text
Mind2Web
→ 只保留缩放后目标元素较大的样本
```

原因不是后者“不能用”，而是它更适合作为补充分析，而不是主训练清洗标准。

## 5. 建议新增：清洗前后的动作分布统计

现文档已经分析了 domain 分布变化，但还缺一个重要的混杂变量：

> **CLICK / TYPE / SELECT 的动作比例是否会因为高度筛选而变化？**

建议至少统计：

| 数据范围 | CLICK | TYPE | SELECT |
|---|---:|---:|---:|
| 原始 train | % | % | % |
| 页高 ≤3000 | % | % | % |

原因：

如果高度筛选后动作分布发生明显变化，那么“加入清洗后的 Mind2Web”这个变量同时包含：

1. 网页视觉数据变化；
2. domain 配比变化；
3. action 配比变化。

这会影响后续结果解释。

因此正式报告中，建议至少同时报告：

- 清洗前后 domain 分布；
- 清洗前后 action 分布。

## 6. 不要把 ScreenAgent 的 1024×768 当成“必须匹配”的目标

现文档用 ScreenAgent 的 1024×768 与 Mind2Web 长截图进行对照，这可以作为直观说明，但不要进一步推导出：

> Mind2Web 必须被裁到和 ScreenAgent 一样的分辨率。

原因：

- 最终虚拟机推理环境本身是 1920×1080；
- 多模态模型会执行内部 resize / smart resize；
- 真正影响 grounding 的不是“原图是否同分辨率”，而是经过模型预处理后，目标 UI 元素是否还保留足够的视觉尺度。

因此建议把主判断放在：

> **模型实际 preprocessing 后的目标元素尺寸**

而不是：

> **原始分辨率是否与 ScreenAgent 一致**

这一点现有文档用 `max_pixels = 896²` 推导缩放后元素高度，其实比单纯比较分辨率更加合理，应继续沿用。

## 7. 建议弱化“一个视觉 token 以下 = 看不见”的绝对表述

现文档写到：

> 目标元素缩到 28 px 以下，垂直方向连一个 token 都占不满——模型不是“定位不准”，是看不见。

这个表达过于绝对。

更稳妥的说法：

> 当目标元素在缩放后的垂直尺寸低于约一个合并视觉 token 的尺度时，其视觉表示会显著变弱，可能增加 grounding 难度。

原因：

模型仍可能利用：

- 周围文本；
- 图标语义；
- 邻近布局；
- 多 token 上下文；

因此“少于一个 token”更适合作为风险指标，而不是“必然不可见”的硬判定。

## 8. 1121 条 bbox 抽样建议补一个简单的不确定性说明

现文档已经正确声明：

> 1121 条 bbox 只是抽样，不等同于全量。

建议再进一步做一个很简单的稳定性验证，例如：

- 将 1121 条样本分成 3~5 份；
- 分别计算 ≤3000 条件下“元素高 ≥14 px”的比例；
- 看各子样本结果是否都接近 78%。

如果波动不大，那么可以更有把握地说明：

> 1121 条抽样对于阈值比较已经具有足够稳定性。

如果暂时不做，也应避免把 78% 写成过度精确的“真实总体比例”。

## 9. 建议确认 `pos_candidates[0]` 的代表性

现文档已说明：

> 不声称 `pos_candidates[0]` 一定是真实目标。

这是一个实际风险。

建议抽查少量样本，确认：

- 第一个正候选是否大多数情况下就是对应操作元素；
- 多正候选样本是否会造成 bbox 尺寸统计偏差；
- CLICK / TYPE / SELECT 三类动作中候选结构是否一致。

不一定要全量处理，但最好做几十条人工抽查，避免后续阈值分析建立在错误 bbox 上。

## 10. 当前建议的最终实验设计

### Phase 1：ScreenAgent baseline

```text
Base Model
→ ScreenAgent
→ LoRA
→ Model A
→ ScreenAgent test + Desktop tasks
```

目的：

> 先取得纯桌面 GUI 数据训练下的基准表现。

这一步必须先完成。

### Phase 2：Mind2Web 增量消融

```text
Base Model
→ ScreenAgent + 清洗后的 Multimodal-Mind2Web
→ LoRA
→ Model B
```

建议主配置：

```text
Mind2Web 页面高度 ≤3000 px
按约 20% 比例混入
```

然后：

```text
Model A vs Model B
```

保持以下配置尽量一致：

- base model
- LoRA rank / alpha
- learning rate
- batch size
- epoch 或训练预算
- seed
- image preprocessing
- evaluation set

这样最终才能较干净地回答：

> **加入经过长度清洗的 Multimodal-Mind2Web，是否能够提升 Desktop GUI Agent 的性能？**

## 11. 如果 Phase 2 是负结果，怎么解释

负结果本身不是失败。

建议预先定义：

### 如果 Model B 优于 Model A

结论：

> 清洗后的网页 GUI 数据对桌面 GUI Agent 具有正迁移作用，可以考虑纳入最终训练方案。

### 如果 Model B 与 Model A 持平或下降

结论：

> 当前形式的 Mind2Web 网页数据未能改善桌面 GUI 能力，可能存在视觉域差异、动作空间差异或目标元素尺度不足等问题，因此不纳入最终训练方案。

然后可选再做：

```text
页高 ≤3000
AND
缩放后目标元素高 ≥14 px
```

作为诊断实验，用于区分：

- 是网页 domain 本身没有帮助；
- 还是过小目标元素降低了训练质量。

这应该是“诊断性实验”，不应覆盖主消融结论。

## 12. 建议最终保留的核心结论

1. Multimodal-Mind2Web 中确实存在较短网页截图，并非全部是超长页面。
2. 页面高度分布没有天然断点，因此清洗阈值必须结合下游视觉可读性设定。
3. 3000 px 是当前模型预处理设定下的合理折中阈值，但不是唯一正确阈值。
4. 页面级高度筛选优先于根据目标 bbox 尺寸筛选，以降低标签相关选择偏差。
5. 清洗会改变 domain 分布，也可能改变 action 分布，必须报告。
6. Mind2Web 不应直接替代 ScreenAgent，而应在 ScreenAgent baseline 之后作为第二阶段增量数据进行消融。
7. 是否最终使用 Mind2Web，以 Model A vs Model B 的实际实验结果为准，而不是预先假设它一定有帮助。

## 13. 建议优先处理顺序

1. 修复并重跑 ScreenAgent，获得有效 Model A baseline。
2. 补充 Mind2Web 清洗前后 CLICK / TYPE / SELECT 分布。
3. 对 `pos_candidates[0]` 做少量人工抽查。
4. 将“3000 是拐点”改成“3000 是当前设定下的折中阈值”。
5. 训练 Model B：ScreenAgent + 清洗后的 Mind2Web。
6. 使用相同测试集比较 Model A / Model B。
7. 只有主消融为负且时间允许时，再跑 `页高≤3000 ∩ 元素高≥14` 的诊断实验。
