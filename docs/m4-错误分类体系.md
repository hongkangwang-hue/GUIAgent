# 错误分类体系（基于实测频次重建）

> M4 交付物第 1 条 / 大纲 W6 任务 1。
> **频次全部来自实测**，不是设想出来的分类。
> 数据源：`docs/m3-trajectories-20260827/`（25 轮 / 185 步）
> 与 `docs/m2-runs/20260827-163522-all-exec-offline-lora-fixed-2.json`。
> 模型：Qwen2.5-VL-3B + adapter `20260827-174327`，客机 1920×1080。

---

## 0. 一句话结论

**失败不是多种原因各占一些，是一种原因占了绝大多数。**

```
94.4% 的子任务在执行 0~1 个动作之后就宣布完成
```

按频次排序，A 类一项就吃掉了绝大部分失败。**优化投入应该压倒性地
向 A 类倾斜**，其余三类目前不值得单独做恢复策略。

## 1. 实测频次总表

25 轮 × 5 任务，共 185 步、90 个以 `done` 收尾的子任务。

## 2. A 类：假 `done`（早停）

### 2.1 定义

模型输出 `{"done": true}` 结束子任务，但程序化判据（进程 / 窗口标题 /
文件内容）显示目标未达成。

### 2.2 典型案例：`close_app` 五轮完全一致

```
step1  {"action":"left_click","x":508,"y":67,"thinking":"点击计算器右上角的关闭按钮"}
       execution_status = ok            ← 点击确实执行了
step2  {"done":true,"thinking":"已经成功关闭了计算器"}
       execution_status = no_action
判定   ✗ 进程 'CalculatorApp.exe' 应已退出；找到 1 个
```

五轮的步数、耗时、坐标、输出全部相同——**这是确定性的失败模式，不是波动**。

### 2.3 病因：模型的完成判据是「我发出了动作」，不是「屏幕变了」

`model_thinking` 的句式直接暴露了这一点（146 条非空、去重 59 条）：

```
5×  因为发送按钮已经被点击，所以任务完成
5×  因为已经输入了文件路径，所以任务完成
5×  因为记事本已经在浏览器中打开了，所以已经完成了任务
4×  因为地址栏已经被点击，所以任务完成
```

**「因为我点了 X，所以任务完成」——句式本身就是以动作代替结果。**

更深一层的成因见 `docs/m3-微调效果对比分析报告.md` §11.7.5：
`done` 是动作集中**唯一不需要参数**的动作（训练集里占 41.6%、答案仅
14 个字符，其余动作 34~55 字符），对交叉熵来说是一条又便宜又常中的路。

> **训练数据无法纠正这一点。** ScreenAgent 的标注是「这一步该做什么」，
> **不含「上一步做成了没有」**。模型没有可学的信号去区分「点了」和「点中了」。
> 因此 A 类必须在**系统层**解决，不能指望换数据或加训练轮次。

### 2.4 检测手段

| 级联层 | 手段 | 成本 | 能挡住的部分 |
|---|---|---|---|
| 1 | 上一步动作后的 OpenCV 帧差 | 毫秒级、免费 | 「点了没中就报完成」——对应 78 次「动作 ok 后立刻 done」 |
| 2 | 程序化判据（进程/标题/文件/UIA 控件） | 毫秒级、免费 | 有明确判据的子任务 |
| 3 | 语义判定（本地 3B 复用常驻权重） | 一次本地推理 | 前两级冲突或都判不了时 |

**级联 1 应该能吃掉大部分**：A 类的主峰是「1 个动作后报 done」（81.1%），
而那个动作若真的命中，屏幕通常会变。

### 2.5 恢复策略

```
① 否决 done，不结束子任务
② 把「上一步没有产生预期变化」写进下一轮的子任务描述
③ 连续 N 次被否决则终止子任务并记为失败，避免死循环
```

**②是关键。** `core/retry.py` 的模块文档已经记录过：单纯把 `left_click`
升级成 `double_click` 改不了模型下一步的判断——**探针实测坐标重复率
75.3%**。要让模型换目标，必须把失败信息回传给它。

### 2.6 现状：完全没有对策

`core/loop.py` 第 332~336 行：

```python
# --- 3. 模型自报完成 ---
if intent.done:
    record.execution_status = "no_action"
    return self._commit(record), (STOP_DONE, ...)
```

**模型说 done，循环立刻返回，一次校验都不做。**
第 7.5 步的屏幕变化检测只在动作执行之后才跑，`done` 走不到那里。

这与 M2 定下的「程序化成功判定，绝不采信模型自报」是**同一条原则**，
只是当时只用在了**轮次级**的验收上，没有用在**子任务级**的推进上。

## 3. B 类：点击落空

### 3.1 定义

动作执行成功（`execution_status = ok`），但没有命中目标，屏幕无变化
或变化与预期无关。

### 3.2 已从 A 类中分离（2026-08-27 追加）

`--reflector` 会自动启用帧差，`record.meta["change"]` 因此有了数据。
Reflector 轮（`lora-reflector`，25 轮 / 220 步）实测：

```
动作执行后屏幕变了   49 次
动作执行后屏幕没变   30 次      ← B 类，占 38.0%
```

**38% 的动作 `execution_status = ok` 但屏幕没有任何变化。**
它们全部执行成功，只是没有命中目标。

`close_app` 是典型：点击 `ok`，但计算器进程仍在。

### 3.3 已有对策

`core/retry.py` 的 `RetryPolicy`：同位置点击无变化 → 升级为双击，
并通过 `hint()` 把「上一次点了没反应」回传给模型。

**默认关闭**，M2/M3 的实测都是关着跑的——打开会改变行为，
不能和历史数据混在一起比。

## 4. C 类：输出解析失败

```
实测 1/185 = 0.5%（parse_error）
```

微调前这是主要问题（离线格式合规率 24.0%），
微调后离线合规率 100.0%、端到端 0.5%。

**已基本消除，不需要专门的恢复策略。** 现有的重试机制足够。

## 5. D 类：坐标塌陷

```
客机 1920×1080  预测 x 中位 508，54.9% 落在 [480,540]，不重复坐标仅 45.1%
离线 1024×768   预测 x 中位 425，19.2% 落在 [480,540]，不重复坐标 82.2%
```

模型坐标空间 0~1000 映射到 1920 宽时 x 乘 1.92，**508 → 真实 x≈975，
正好是屏幕水平中线**。

**只在客机上发生，训练同尺寸图上正常。** 疑似宽高比造成
（训练 4:3，客机 16:9），详见 §11.7.7。

**这不是恢复策略能解决的类别**——它是预处理问题。验证方法是
把验证集 letterbox 成 16:9 后重跑离线评测。

## 6. 优先级结论

```
A 类   94.4%    → Reflector 级联 1+2，本阶段主要工作
B 类   含于 A   → 先打开帧差把它分离出来，再谈
C 类    0.5%    → 不做
D 类   离线可测 → 一次 letterbox 实验即可定性，与恢复策略无关
```

**不为 C、D 类写恢复策略。** 分类体系的作用是把投入放对地方，
把四类都做一遍恢复策略是把 0.5% 和 94.4% 当成同等重要。

## 7. Reflector 实测（2026-08-27）

单变量对照：唯一差别是 `--reflector`，模板同为 `executor_v0`，
`escalate_on_no_change` 两轮都是 `False`（存档字段可核）。

### 7.1 成功率

| 任务 | 无 Reflector | 有 Reflector |
|---|---:|---:|
| `open_browser` | 3/5（60%） | **5/5（100%）** |
| `search_content` | 0/5 | 0/5 |
| `open_file` | 0/5 | 0/5 |
| `send_message` | 0/5 | **3/5（60%）** |
| `close_app` | 0/5 | **2/5（40%）** |
| **合计** | **3/25 = 12%** | **10/25 = 40%** |

三个佐证指标同向变化：

```
模型自报完成            24/25      →  22/25
自报完成但判定未通过     21         →  12          少 43%
零动作报完成的子任务     12/91(13%) →  7/84(8%)
```

### 7.2 级联触发率（M4 要求记录的关键指标）

```
Reflector 判定 138 次 / 220 步

accept     74   53.6%
reject     57   41.3%
unknown     7    5.1%
```

**级联 1 单独出了 94.9% 的结论。** 里程碑设计的假设
「绝大多数步骤应在前两级出结论」成立——**且级联 1 一级就够，
级联 2/3 暂时用不上**（例外见 §8.4）。

### 7.3 一处必须修正的判断：反馈方式决定成败

§2.5 曾引用 `core/retry.py` 的探针实测「坐标重复率 75.3%」，
据此预判「反馈回传也纠正不了」。**实测推翻了这个预判：**

```
否决之后模型改做了什么   left_click 7 次 / type 8 次 / 解析失败 3 次
其中坐标与上一次相同     0 次
```

**0 次重复。** 差别在反馈内容：

| | 反馈内容 | 坐标重复率 |
|---|---|---:|
| `retry.py` | 升级动作类型（单击→双击），坐标不变 | 75.3% |
| `Reflector` | 「上一步没有产生变化，很可能没命中，不要报告完成」 | **0%** |

**告诉模型「动作没生效」和告诉它「再试一次」，效果完全不同。**
75.3% 那个数字来自另一种反馈方式，不能外推到这里。

### 7.4 `open_file` 是最有价值的负例：级联 2 的存在理由

```
任务              accept  reject  unknown   成功
open_browser        15       0       0      5/5    从没被否决，本来就做对了
send_message        13      26       2      3/5    否决最多，救回 3 个
open_file           25      20       5      0/5    否决 20 次仍然全败
search_content      16       7       0      0/5
close_app            5       4       0      2/5
```

`open_file` 被否决 20 次、模型确实一直在改动作，但仍然 0/5。判定信息：

```
✗ 进程 'notepad.exe' 应在运行；未找到
当前窗口：记事本 - 搜索 - 个人 - Microsoft Edge
```

**模型在 Edge 里搜索「记事本」这三个字，而不是打开记事本程序。**

这是**任务理解错误**，不是执行未生效——帧差每次都显示「变了」，
级联 1 判定 `accept`，但方向从一开始就错了。

> **这正是级联 2（程序化判据）该管的。** 检查「`notepad.exe` 进程是否存在」
> 比看屏幕变没变有力得多。
>
> **级联 1 管「动作有没有生效」，级联 2 管「方向对不对」**
> ——这个分工现在有数据支撑，不再是设计时的猜想。

### 7.5 两条必须标注的限制

1. **快照不同。** 无 Reflector 那轮从 `eval-baseline 2` + 手工装依赖起跑；
   Reflector 这轮从 `eval-baseline-llm` 起跑。**两次的客机环境是否一致
   无法验证**，12% → 40% 中可能含环境差异。
   这是继「17% 那次快照未记录」之后的**第二次同类问题**——
   **从本轮起必须把快照名记进存档。**
2. **n=25，各跑一次。** 幅度很大，但没有重复实验。

### 7.6 复现

```bash
# 客机，与无 Reflector 那轮只差 --reflector
python scripts/run_basic_tasks.py --execute     --provider selfhost --base-url http://192.168.112.1:8000/v1     --executor-template executor_v0 --reflector     --tag lora-reflector --repeats 5
```

存档 `docs/m2-runs/20260827-192807-all-exec-offline-lora-reflector.json`，
轨迹 `docs/m4-trajectories-reflector-20260827/`（只导结构化，不导 `frames/`）。

## 8. 本文档不声称的事

- **不声称这四类穷尽了所有错误。** 它们是 25 轮 185 步里观察到的，
  更长的任务（M4 交付物 4 要求 8 步以上）可能暴露新类别。
- **不声称 A 类频次可外推。** 25 轮、5 个任务、单一模型。
- **不声称 B 类真的独立存在。** 目前它只是 A 类里一个尚未分离的子集，
  分离需要帧差数据。
- **不声称 12% → 40% 的幅度可复现。** 各跑一次、客机快照不同，
  见 §7.5。
- **不声称级联 1 能挡住多少。** 「应该能吃掉大部分」是推断，
  触发率是 M4 要实测记录的指标，不是现在能给的数。
