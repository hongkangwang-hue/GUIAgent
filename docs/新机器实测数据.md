## 2. ⚠ 显卡当前处于故障状态（Code 43）—— 未解决

`nvidia-smi` 无法运行，报 "insufficient permissions"。该报错具有误导性，**真实原因不是权限**：

```
Get-CimInstance Win32_PnPEntity | Where-Object { $_.Name -like "*RTX 5060*" }

Name                   : NVIDIA GeForce RTX 5060 Laptop GPU
ConfigManagerErrorCode : 43        ← "Windows 因该设备报告故障而将其停止"
Status                 : Error
```

设备已被 Windows 枚举（WMI 能列出型号与驱动版本）但处于错误状态，因此：

- `nvidia-smi` 全部查询失败 → **`memory.free` 无法采集**
- `torch.cuda.is_available()` 返回 `False`，底层报 `cudaGetDeviceCount() returned cudaErrorNotSupported`

**这不是 PyTorch 装错版本。** torch 的 wheel 选对了，`torch.cuda.get_arch_list()` 确认含 `sm_120`（见下节）。GPU 相关的两个警告项要等 Code 43 在物理机上修好（重装驱动 / 检查 BIOS 的 MUX 与独显开关 / 重启）之后才能复验。


## 6. ⚠ PaddlePaddle 3.3.1 需要关闭 oneDNN

paddlepaddle 3.3.1 的新执行器（PIR）在 oneDNN 路径上有 bug，OCR 推理直接崩：

```
NotImplementedError: (Unimplemented) ConvertPirAttribute2RuntimeAttribute
not support [pir::ArrayAttribute<pir::DoubleAttribute>]
(at ..\paddle\fluid\framework\new_executor\instruction\onednn\onednn_instruction.cc:118)
```

**绕过方式**——设环境变量后 OCR 正常：

```powershell
$env:PADDLE_PDX_ENABLE_MKLDNN_BYDEFAULT = "False"
```

注意 `FLAGS_use_mkldnn=0` 和 `FLAGS_enable_pir_api=0` **都不管用**，PaddleX 用自己的开关。建议写进 `.env` 或运行脚本，否则每次新开终端都要重设。

## 8. 本次为适配新版本所做的代码改动

`perception/ocr_engine.py` 的 `_parse` 只认 paddleocr 2.x 的 list 输出，而本机装的
**paddleocr 3.7.0 改为按图返回映射**（`rec_texts` / `rec_polys` / `rec_scores` 三个
等长列表），导致 `KeyError: 0`。已新增 `_parse_v3` 分支处理该格式，2.x 路径保持不变。

这正是该函数原注释预判的情况——「OCR 库的输出格式在版本间变过好几次，写死一种解析必然踩雷」。
