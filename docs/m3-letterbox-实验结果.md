# letterbox 实验：宽高比**不是** x 坐标塌陷的原因

> 对应 `docs/m3-微调效果对比分析报告.md` §11.7.7 提出的假设。
> 日期：2026-08-27　　结论：**假设被否定。**

## 1. 要验的假设

§11.7.7 的实测：

```
客机 1920×1080（16:9）  预测 x 中位 508，54.9% 落在中心区 [480,540]，不重复坐标 45.1%
离线 1024×768（4:3）    预测 x 中位 425，19.2% 落在中心区，不重复坐标 82.2%
```

**塌陷只在客机上发生。** 当时提出的解释是宽高比：
训练图 4:3（1.33），客机 16:9（1.78），坐标归一到 0~1000 空间时
16:9 的水平方向被压缩得更厉害，模型只见过 4:3，于是回退到均值。

## 2. 做法

把验证集 **补黑边**成 16:9（1024×768 → 1365×768，左右各补 170px）。

**补黑边而不是拉伸。** 拉伸会同时改变内容形状，那就不是单变量；
补黑边只改画幅，内容像素一个不动。

真值坐标同步变换（`point_norm` / `point_px` / `answer` / `params.point`）。

只跑带坐标的 99 条——x 塌陷只与它们有关。
两组都用 `--local`（无损），与 `after-fixed` 口径一致。

## 3. 判据必须拿真值做对照

letterbox 之后内容被挤进 `[125, 875]`，**真值本身的中心集中度就会上升**：

```
原图 4:3    真值 x 落在中心区  16.2%
letterbox   真值 x 落在中心区  19.2%    ← 天然上升，不是模型的问题
```

所以判据是：

```
预测集中度 ≈ 19%      → 宽高比不是原因
预测集中度 ≈ 50% 以上  → 宽高比是原因，与客机的 54.9% 对上
```

**只看预测不看真值会得出假阳性。**

## 4. 结果

| | n | P25 | 中位 | P75 | 中心区 | 不重复 |
|---|---:|---:|---:|---:|---:|---:|
| 原图 4:3 预测 x | 54 | 125 | 425 | 528 | **13.0%** | **88.9%** |
| letterbox 16:9 预测 x | 55 | 254 | 526 | 672 | **10.9%** | **90.9%** |
| 客机 1920×1080 预测 x | 51 | 405 | 508 | 508 | **54.9%** | **45.1%** |

**补成 16:9 之后 x 完全没有塌陷。**
中心集中度不升反降（13.0% → 10.9%），不重复坐标占比还略有上升。

而客机是 54.9% / 45.1%——**差得极远。**

> **假设被否定。** 宽高比不是客机 x 坐标塌陷的原因。

## 5. 一处实验缺陷（影响副结论，不影响主结论）

第一版脚本只变换了 `answer` 与 `params["point"]`，**漏了 `point_norm`**
——而 `eval/action.py:513` 读的正是 `point_norm`。

后果：

```
误差 / 命中率两列    作废   真值在 4:3 空间，预测在 16:9 空间
预测 x 的分布       有效   模型在 letterbox 图上的原始输出，与真值标签无关
```

**主问题恰好只靠预测分布就能回答**，所以结论不受影响。
脚本已修（`scripts/make_letterbox_val.py`），`point_norm` 变换零错误。

> 教训：**变换坐标前先查清楚下游读的是哪个字段**，不要只改看得见的那个。
> 同一份真值在这个项目里存了四处（`point_norm` / `point_px` /
> `answer` / `params.point`），改一处不改其余就会静默错位。

**副问题（letterbox 会不会伤害精度）未重跑。** 既然 letterbox 复现不出塌陷，
它就不是修法，评估其副作用已无决策价值。

## 6. 剩下的候选

排除宽高比之后：

| 候选 | 可疑度 | 成本 | 怎么测 |
|---|---|---|---|
| **③ 提示词不同** | **高** | 40 分钟 | 客机走 `executor_v0`（动作说明由 `ACTION_SPECS` 现场生成），离线走训练时的 `SYSTEM_PROMPT`。**同一批图、只换提示词**即可分离 |
| ④ JPEG 压缩 | 中 | 40 分钟 | 客机走 HTTP（q85 有损），离线 `--local` 无损。评测时先按 q85 压一遍再喂 |
| ① 分辨率绝对值 | 中 | 要造数据 | 把验证集放大到 1920×1080 再跑 |
| ② 界面内容分布 | 低 | 难 | 客机是 Windows 桌面，ScreenAgent 是别的环境；需新采集 |

**③ 最可疑，而且如果坐实，修法比 letterbox 还便宜**——
客机推理时改用训练时的提示词即可，`llm/qwen_vl_local.py` 里
已有 `pin_prompt=True` 这个参数。
