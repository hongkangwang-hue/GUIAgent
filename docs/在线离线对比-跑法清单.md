> 目的：为老师补充要求「做一个在线版和一个离线版」产出实测数据。

## 0. 要跑哪几组，为什么

| 组 | 命令上的差别 | 回答哪个问题 | 依据 |
|---|---|---|---|
| **A 在线** | `--provider dashscope` | 基线 | 大纲 W4 |
| **B 离线-基座** | `--provider selfhost` + 宿主机不挂 adapter | 微调前 | 大纲 W5 任务 3 |
| **C 离线-微调** | `--provider selfhost` + 宿主机挂 adapter | 微调后 | 大纲 W5 任务 3 |

- **B vs C** = 大纲 W5 任务 3「对比微调前后模型在 GUI 任务理解与动作生成上的效果」，
  **在真实任务上**，不只是验证集

三组共用同一个脚本、同一份任务清单、同一套提示词。**不同就不是模型的差值了。**

## 2. 宿主机：起模型服务

### 2.1 放行防火墙（只做一次）

Windows 防火墙默认挡掉入站 8000。**这一步不做，客机会卡在连接超时**，
而超时的报错完全看不出是防火墙。

以**管理员身份**开 PowerShell：

```powershell
New-NetFirewallRule -DisplayName "GUIAgent 本地模型服务(VMnet8)" `
    -Direction Inbound -Protocol TCP -LocalPort 8000 `
    -RemoteAddress 192.168.112.0/24 -Action Allow
```

`-RemoteAddress` 限定只有 VMnet8 网段能进。**不要省掉它**——本服务不做鉴权。

### 2.2 起服务

```powershell
# B 组：离线-基座
python scripts\serve_local_model.py --host 0.0.0.0 --preload

# C 组：离线-微调
python scripts\serve_local_model.py --host 0.0.0.0 --preload `
    --adapter finetune\outputs\20260824-170900\adapter
```

`--preload` 在起服务时就把权重装进显存。不加的话第一个请求要多等约 7 秒，
**那 7 秒会算进第一条任务的延迟里，把首轮数据污染掉**。

看到这行才算就绪：

```
本地模型已就绪：Qwen/Qwen2.5-VL-3B-Instruct + …，4-bit NF4，max_pixels=802816，耗时 7.0s
```

**这个窗口全程别关。** 跑完一组要换 adapter 时，Ctrl+C 停掉再按另一条命令起。

## 3. 客机：连通性自检

**不需要改 `.env`。** 自建服务不校验鉴权，端点由 `--base-url` 在命令行给
——少一步手工编辑，就少一处能改错的地方。

```powershell
curl http://192.168.112.1:8000/health
```

期望：

```json
{"status":"ok","model":"Qwen/Qwen2.5-VL-3B-Instruct","adapter":"...","loaded":true}
```

| 症状 | 原因 |
|---|---|
| 连接超时 | 防火墙（2.1）或服务没加 `--host 0.0.0.0` |
| `loaded: false` | 服务起了但没 `--preload`，第一次请求会慢 |
| `adapter: null` 而你要跑 C 组 | 起服务时忘了 `--adapter` |

**`adapter` 那一栏一定要看。** B 组和 C 组的命令只差宿主机起的是哪个服务，
起错了跑完 50 分钟才发现，两组数据一模一样。

`192.168.112.1` 是宿主机在 VMnet8 上的地址（2026-08-24 实测）。变了的话，
宿主机 `ipconfig` 找 `VMware Network Adapter VMnet8`。

## 4. 跑

三组都在**客机**里跑。每组之前确认客机桌面是干净的初始状态。

```powershell
cd C:\Users\22900\GUIAgent

# A 组 在线
python scripts\run_basic_tasks.py --execute --repeats 5 --provider dashscope --tag online

# B 组 离线-基座（宿主机起的是不带 adapter 的服务）
python scripts\run_basic_tasks.py --execute --repeats 5 --provider selfhost --base-url http://192.168.112.1:8000/v1 --tag base

# C 组 离线-微调（宿主机起的是带 adapter 的服务）
python scripts\run_basic_tasks.py --execute --repeats 5 --provider selfhost --base-url http://192.168.112.1:8000/v1 --tag lora
```

> **B 与 C 只差 `--tag`。** 真正的区别在宿主机起的是哪个服务——所以跑 C 组前
> 必须先 `curl /health` 确认 `adapter` 不是 `null`（见 §3）。
> `--tag` 只是给存档起名，**它不会改变实际跑的模型**。

抬头会打印后端与数据边界，开跑前核对一眼：

```
  后端      在线 / 阿里云百炼 / qwen3-vl-8b-instruct
  数据边界  截图上传到平台服务器
```

### 跑多久

按 M2 实测（`docs/m2-runs/20260824-003649-all-exec.json`，25 轮均 25.3 秒）：

| 组 | 每步延迟 | 25 轮预计 |
|---|---|---|
| A 在线 | 1.3 秒（快时）/ 11 秒（慢时） | **10 分钟 ~ 2 小时** |
| B / C 离线 | 5–12 秒（实测） | **50 ~ 75 分钟** |

API 慢时段实测到 11277ms/step，是快时段的 8.97 倍。**A 组尽量和 B/C 同一天跑**，
否则延迟对比里混进的是时段差异。

### 跑的时候

- **别碰鼠标键盘。** 碰了就在那一轮的记录里标 `excluded`，不要假装没发生
- 急停：`Ctrl+Alt+Q`，或把鼠标甩到屏幕角落
- 中途停了可以重跑该组，存档不会互相覆盖

## 5. 存档

`--tag` 进文件名，**不需要手工改名**：

```
docs/m2-runs/<时间戳>-all-exec-online-online.json
docs/m2-runs/<时间戳>-all-exec-offline-base.json
docs/m2-runs/<时间戳>-all-exec-offline-lora.json
```

JSON 里还有 `backend` / `offline` / `tag` 三个字段，记着这一份是谁跑的。

> `docs/m2-basic-tasks-raw.json` 只有「在线 + 全量 + `--execute`」才会被覆盖。
> 离线跑、`--only` 跑、演练跑都不动它——那是 M2 验收报告引用的数据。

### 三条必须写明的限制

1. **验证集上的 85.2% 推不到这里。** 走 HTTP 时截图经 JPEG q85 压缩，
   而 `eval/action.py --local` 是无损的。两组数不能互推。
2. **C 组属于分布外。** adapter 只在 `left_click / double_click /
   right_click / mouse_move` 四个动作上训练过，而 executor 提示词的动作空间大得多。
   实测它仍会输出 `done` 与 `thinking`，但这是实测结果，不是设计保证。
3. **few-shot 会让 3B 模型逐字照抄示例。** 实测四个目标里抄了 2 个，
   抄出来的坐标是示例里的常数 `(470, 750)`——**格式 100% 合规，坐标却是错的**。
   这个现象在 A 组（8B 云端模型）上未观察到。W5 任务 4 的提示词消融要专门量它。
