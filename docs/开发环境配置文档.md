## 1. 环境基线

本项目跨两台机器:**开发机**完成 M1–M2,**目标机**承担 M3 的本地模型部署。代码经 git 同步,因此配置必须在两台上都成立。

| 项 | 开发机(当前) | 目标机(M3) | 复现最低要求 |
|---|---|---|---|
| GPU | RTX 3060 Laptop **6GB**(Ampere / **sm_86**) | RTX 5060 Laptop 8GB(Blackwell / **sm_120**) | 可无 GPU 完成 M1–M2 |
| 驱动 | 546.92(支持至 CUDA 12.3) | 需支持 CUDA 12.8+ | — |
| 内存 | **16GB** | 32GB | 16GB(M1–M2) |
| 系统 | Windows 11 26100 | Windows 11 | Windows 10 1809+ |
| 磁盘 | — | 1TB NVMe | 预留 80GB(模型 25GB + 数据集 15GB + 虚拟机 40GB) |
| Python | 3.10 | 3.10 | 3.10 / 3.11,**不用 3.12+**(`paddlepaddle`、`uiautomation` 的 wheel 供给滞后) |
| 包管理 | conda 建环境,**所有包一律 pip 装** | 同 | 混用两者管理同一批包会产生难排查的冲突 |

**两处差异会实际影响操作,不是备注:**

1. **PyTorch 的 CUDA 版本按显卡架构选,不能照抄**(见第 3 节)。sm_86 用 cu121,sm_120 必须 cu128+。
2. **虚拟机内存分配按各机总内存定**(见第 4 节)。开发机 16GB 只能给客机 6GB,目标机 32GB 才能给 12GB。

`requirements.lock.txt` 是**机器相关的**,换机后需重新生成,不要直接套用另一台的。

## 2. 安装序列

```powershell
# 环境
conda create -n gui-agent python=3.10 -y
conda activate gui-agent
python -m pip install --upgrade pip

# PyTorch —— cu 版本按显卡架构选，先跑 nvidia-smi --query-gpu=compute_cap --format=csv
#   sm_86 (RTX 30xx / Ampere)      → cu121
#   sm_89 (RTX 40xx / Ada)         → cu121 或 cu124
#   sm_120 (RTX 50xx / Blackwell)  → cu128 或更高，低于此的构建无可用 kernel
# 详见第 3 节。装错的后果不是报错而是"能导入、一运算就崩"。
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

# 感知与控制
pip install dxcam                    # Windows 首选截图引擎（DXGI 桌面复制）
pip install mss pyautogui pynput opencv-python pillow pyperclip uiautomation

# OCR —— 必须排在 torch 之后！easyocr 依赖 torch，先装它的话 pip 会拉一个
# CPU 版 torch 把依赖占住，之后 cu 版就装不进去了（依赖已满足，pip 不会主动换）
pip install paddlepaddle paddleocr easyocr

# 大模型与 Agent
pip install langchain langchain-openai transformers accelerate peft bitsandbytes

# 数据与分析
pip install datasets pandas matplotlib seaborn openpyxl

# 工程化
pip install pytest pytest-cov ruff pre-commit rich typer python-dotenv
pre-commit install

# 验证与锁定
python scripts/env_check.py
pip freeze > requirements.lock.txt
```

五类分组对应 M0《技术栈落实对照》。**一次装齐**——后续里程碑只下载模型权重与数据集,不再新增基础依赖。

## 3. ⚠ PyTorch 的 CUDA 版本必须匹配显卡架构

**这是本项目唯一的硬件兼容风险,而且换机器时必须重新判断一次。**

PyTorch 的每个 `cuXXX` 构建只编译了特定几种算力的 kernel。显卡算力不在其中时,**`import torch` 不报错、`torch.cuda.is_available()` 甚至返回 `True`,直到第一次真正在 GPU 上运算才崩**:

```
RuntimeError: CUDA error: no kernel image is available for execution on the device
```

有时会先出现更明确的一条:

```
NVIDIA GeForce RTX 5060 Laptop GPU with CUDA capability sm_120 is not compatible
with the current PyTorch installation.
```

### 先查算力，再选版本

```powershell
nvidia-smi --query-gpu=name,compute_cap,memory.total,driver_version --format=csv
```

| 算力 | 架构 | 显卡 | 装什么 |
|---|---|---|---|
| sm_86 | Ampere | RTX 30xx | **cu121**(本项目开发机) |
| sm_89 | Ada | RTX 40xx | cu121 / cu124 |
| **sm_120** | **Blackwell** | **RTX 50xx** | **cu128 或更高**(本项目目标机) |

```powershell
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
#                                                                          ^^^^^ 按上表替换
```

安装前到 [pytorch.org](https://pytorch.org/get-started/locally/) 版本选择器确认当前对应关系(官方索引路径会随版本变化)。不需要单独装 CUDA Toolkit,pip wheel 自带运行时;驱动支持上限见 `nvidia-smi` 右上角的 `CUDA Version`。

### 验证 —— `is_available()` 不是判据

```python
import torch
capability = torch.cuda.get_device_capability(0)
arch = f"sm_{capability[0]}{capability[1]}"
print(torch.__version__, arch)
print(arch in torch.get_arch_list())        # 必须 True
x = torch.randn(1024, 1024, device='cuda')
print((x @ x).sum().item())                 # 必须跑完
```

`is_available()` 只检查驱动与运行时能否初始化,**不检查有没有你这张卡的 kernel**。最后两行才是判据。`scripts/env_check.py` 已经按这三重判据实现,直接跑它即可,不需要手敲。

### 装不对不阻塞前四周

M1/M2 唯一用 GPU 的是 PaddleOCR 加速,而它跑 CPU 完全可用(单张图几十毫秒 → 几百毫秒);规划层走 API 不占显存。因此 `env_check.py` 把**全部 GPU 检查归为警告项**,M3 前解决即可;届时仍未解决则 grounding 模型改在租用 GPU 上部署(M0 风险表已列)。

**PaddlePaddle 装 CPU 版。** 它的架构支持进度独立于 PyTorch,不要假设 torch 装对了 Paddle 的 GPU 版就能用。

### bitsandbytes 单独实测

它的 kernel 也需针对新架构单独编译,与 PyTorch 支持与否是两件事——**换到 sm_120 的目标机后必须重测**。不看版本号,直接跑(用小模型探路,不必等 M3 下载 3B):

```python
import torch
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
cfg = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_compute_dtype=torch.bfloat16)
m = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct",
                                         quantization_config=cfg, device_map="cuda:0")
print(f"OK, {torch.cuda.memory_allocated()/1024**3:.2f} GB")
```

## 4. 隔离虚拟机

**Agent 的一切键鼠执行只发生在虚拟机内,宿主机不受控制。** 硬性前置条件,任何里程碑不得绕过。

| 项 | 配置 |
|---|---|
| 方案 | VMware / VirtualBox + Windows 11 客机(备选:Docker + Xvfb;Windows Sandbox) |
| **客机内存** | **开发机(16GB):给客机 6GB。目标机(32GB):给客机 12GB** —— 见下 |
| 客机 CPU | 2-4 核,留至少一半给宿主机 |
| GPU 直通 | **不需要**。模型跑宿主机,宿主机截 VM 的屏、算坐标、发键鼠事件 |
| 分辨率 | 固定为一个已知值并记录,坐标系统模块依赖它 |
| 快照 | **装好立刻存干净快照**,M2–M5 每轮评测从该快照恢复 |

**内存分配不能照抄另一台机器。** 宿主机要同时跑:Windows 本身、IDE、Python 进程、以及 M3 起本地 grounding 模型。开发机总共 16GB,给客机 12GB 会只剩 4GB,连 IDE 加模型都装不下,结果是宿主机疯狂换页、截图延迟飙升——而截图延迟正是 M1 的验收项之一。**按"总内存的 1/3 到 2/5"给客机**是安全区间。

### 数据边界 —— 虚拟机不解决隐私问题

虚拟机解决**执行隔离**,不解决**数据隐私**。规划层走云端 API,**VM 内的截图会被上传出去**。因此客机按"可公开的测试环境"建:

- ✅ 只装测试软件、只用为本项目新建的测试账号、只放预置测试文件
- ❌ 不登录任何真实个人账号,不放真实聊天记录、邮件、通讯录、支付信息或含个人身份信息的文档

## 7. `scripts/env_check.py` 判据

**必过项**(失败即阻塞,退出码 1):

| 检查 | 判据 |
|---|---|
| Python 版本 | 3.10 / 3.11 |
| 依赖完整性 | 第 2 节全部包可 import |
| mss 截图速度 | 单帧 < 15ms |
| DPI 缩放检测 | 能读到当前缩放比例 |
| OCR CPU 推理 | PaddleOCR 能在 CPU 上识别测试图 |

**警告项**(仅提示,不影响退出码,**但 M3 开工前必须全部转绿**):

| 检查 | 判据 |
|---|---|
| CUDA 可用性 | `torch.cuda.is_available()` |
| **sm_120 支持** | `get_device_capability()==(12,0)` **且** `'sm_120' in get_arch_list()` **且** GPU 矩阵乘跑完 |
| 显存容量 | ≥ 8GB |
| bitsandbytes 4-bit | 第 3 节探路脚本跑通 |
| OCR GPU 推理 | PaddleOCR GPU 模式可用 |

## 8. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `no kernel image is available` / `sm_120 is not compatible` | PyTorch 构建不含 sm_120 | 重装 cu128+,见第 3 节 |
| `is_available()` 为 True 但运算崩溃 | 只验了初始化,未验 kernel | 用 `get_arch_list()` + 实际矩阵乘复验 |
| 包装了却 import 不到 | pip 指向 base 环境 | `python -c "import sys; print(sys.executable)"` 确认路径含 `envs\gui-agent` |
| PaddleOCR 报缺 DLL | 缺 VC++ 运行库 | 安装 Microsoft Visual C++ Redistributable |
| 截图坐标与点击位置偏移 | DPI 缩放未处理 | 进程启动时 `SetProcessDpiAwareness(2)` |
| `pyautogui.write()` 打不出中文 | 只发送 ASCII 键码 | 改走 `pyperclip` + `Ctrl+V` |
| matplotlib 中文显示方框 | 未指定中文字体 | `rcParams['font.sans-serif']=['Microsoft YaHei']`;`axes.unicode_minus=False` |
| `FAILSAFE` 甩不出去 | 鼠标被 Agent 占用,人机抢光标 | 用 `pynput` 全局热键(如 `Ctrl+Alt+Q`)作第二道刹车 |
| 虚拟机内截图全黑 | 客机启用硬件加速渲染 | 关闭客机 3D 加速,或走 VM 自带截图通道 |
