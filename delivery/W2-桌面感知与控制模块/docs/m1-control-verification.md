## 阅读说明

本文件由脚本逐次追加，**包含调试过程中的失败记录**。前三条不是系统缺陷，
是验证脚本自身的缺陷，均已修复：

| 记录 | 表面现象 | 真实原因 | 修复 |
|---|---|---|---|
| 22:33 | DPI 记成 100%（实为 150%） | `dpi_describe()` 在 `enable_dpi_awareness()` 之前调用，未启用感知时 Windows 会对进程报回逻辑值 | commit `ecfbbfb` |
| 22:36 | 12 点中 11 点 FailSafeException | 坐标链检查故意测四个角，而屏幕四角正是 PyAutoGUI FAILSAFE 的触发点——两条验收要求（3 与 7）在此冲突 | commit `14d376a`：角点改用纯计算验证，真移鼠标的点内缩 1 格 |
| 22:40 | 孤立一点偏 7px | 读数时物理鼠标被碰到。系统性坐标错误会让 12 点全偏且成比例，孤立一点偏移不符合该形态 | commit `28cd267`：连读两次检测外力干扰，不稳则重试 |

**22:42 那条是修复后的有效结果**：12 个目标点最大偏差 0.0px，无干扰重试。

## 客机记录说明（2026-08-23）

08-23 起本文件同时包含**宿主机**与**客机**两组数据。M1 验收标准 5、6 要求

### 15:03 那条失败也不是系统缺陷，是操作指引造成的

| 表面现象 | 真实原因 |
|---|---|
| 坐标链最大偏差 **681px** | 脚本要求全程不碰鼠标，而当时的指引让人「回车后赶紧点一下记事本」。那一下点击被干扰检测正确识别（详情里写了「读数不稳定，疑似外部鼠标干扰」），但精度已废 |
| 中文输入读回 `'C:\\c测试'` | 同一条指引的另一半后果。中文输入检查通过 UIA 在**前台窗口**找文本框，而到那一步时前台已经回到 PowerShell，中文被打进了终端，读回的是 PowerShell 窗口的文本 |

两项失败源自同一条自相矛盾的指引：**「切到记事本」与「别碰鼠标」不可能
同时满足**。修复不在检查逻辑，而在流程——`verify_control.py` 加了 `--delay`
（commit `6ea440c`），拆成两次跑，各自只有一条简单规则：

```bash
python scripts/verify_control.py --skip-input   # 全程不碰鼠标键盘
python scripts/verify_control.py --only input --delay 5   # 倒计时里切窗口
```

**15:09 之后的记录是按新流程跑的有效结果。**

### 客机 vs 宿主机（同一口径）

| 项 | 宿主机 | 客机 |
|---|---|---|
| 分辨率 | 2560×1600 | 1920×1080 |
| 截图引擎 | dxcam | **dxcam**（虚拟机里可用，未降级） |
| 取当前画面 p50 | 0.029 – 0.058 ms | **0.043 ms** |
| 坐标链最大偏差 | 0.0 px | **0.0 px** |
| 急停热键延迟 | 247 ms | **271 ms** |

急停在客机里慢约 24ms，来自 VMware 输入捕获这一层，两者都远低于 500ms 判定线。

> 建客机前曾预判两件事，**实测都被推翻**，记录在此：
> ① dxcam 依赖 DXGI，虚拟机里应当不可用 —— 实际可用，且未降级；
> ② `Ctrl+Alt+Q` 会被 VMware 的释放焦点前缀截走 —— 实际能到达客机。
